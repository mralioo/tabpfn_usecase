Model comparison — XGBoost vs TabPFN-3.5
Select a closure scenario from the chat to compare how the XGBoost baseline and TabPFN-3.5 each size up the network impact — affected stations, P(≥ own P90 load), inference time, and how much data each model actually used. Both calls are genuine model inference against this repo's real tabpfn_lab pipeline, not canned numbers.
Methodology Topology, line/operator metadata and 15-min flow statistics are the real Berlin_Ubahn_Alstom_data files (168 stations, 182 links, 8 lines). Closure scenarios come from the dataset's own closures_pre_innotrans.csv / closures_rest.csv records. XGBoost is fit locally on the full chronological training split; TabPFN-3.5 runs as a genuine tabpfn_client API call against an 8,000-row in-context sample — both through this repo's tabpfn_lab package, the same code the MCP server and Streamlit dashboard use. If TABPFN_API_TOKEN is missing or a call fails, that side falls back to a labelled, deterministic simulation so the app still runs end to end offline.
