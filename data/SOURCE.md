# Data provenance — two datasets, two roles

`data/` holds one subfolder per dataset. Each has its own loader module under
`tabpfn_lab/datasets/`. Neither was collected by this project.

| Folder | Role in this repo | Size | Real / simulated | Committed to git? |
| --- | --- | --- | --- | --- |
| `Berlin_Ubahn_Alstom_data/` | The use case: anomaly early warning, MCP + agent, webapp | 1.5M rows | Simulated flow/closures, real geometry/events/weather | Yes (small CSVs) |
| `DB_data/` | TabPFN-3.5 vs. XGBoost, big real data | ~1.5-2M rows/month | Real | No (fetched on demand) |

## Berlin U-Bahn (Alstom / InnoTrans 2026)

Generated by **Alstom's data team** for the **InnoTrans 2026 hackathon** (Berlin U-Bahn
operations scenario): real station/line/weather geometry combined with simulated passenger flow,
closures and energy-consumption series. Full details, splits and the dataset schema:
[`Berlin_Ubahn_Alstom_data/SOURCE.md`](Berlin_Ubahn_Alstom_data/SOURCE.md).

Reused here, unmodified, for the **TabPFN-3.5 hackathon** (platform.priorlabs.ai) under that
hackathon's rule 3.2 ("the linked repository must contain ... your input data or make it
available at a public URL"). This repo makes no ownership claim over the data itself — only over
the code in `tabpfn_lab/`, `mcp_server/`, `agent/`, `webapp/`, `notebooks/` and `scripts/`.

## Deutsche Bahn (`DB_data/`)

A large, real, same-topic dataset for a harder benchmark than Berlin's simulated, strongly
periodic flow can support (see the README's "A bigger, harder benchmark" section). **Deutsche
Bahn** (German national rail) per-stop delay records, from
[piebro/deutsche-bahn-data](https://huggingface.co/datasets/piebro/deutsche-bahn-data) on
Hugging Face (CC BY 4.0, built from Deutsche Bahn's own public timetable/delay feeds — project
page: [github.com/piebro/deutsche-bahn-data](https://github.com/piebro/deutsche-bahn-data)).
Fetched on demand via `tabpfn_lab/datasets/deutsche_bahn.py` (`huggingface_hub.hf_hub_download`,
no auth for this public dataset) and mirrored into `DB_data/` (gitignored) after the first call.

## Lineage

This repository started from **[NextMove](https://github.com/mralioo/NextMove)**, a multi-agent
"AI team for the control room" built for the InnoTrans 2026 hackathon on the Berlin U-Bahn
dataset. NextMove used `tabpfn-client` (TabPFN v3.5) as one tool among many behind a four-role
agent pipeline (Dispatcher → Analyst ⇄ Inspector → Writer). Working on that project is what
surfaced how good tabular foundation models have gotten — this repo pulls that thread on its own,
independent of NextMove's broader control-room scope, specifically for the TabPFN-3.5 hackathon:
go deeper on what TabPFN-3.5 can predict and classify, across more than one dataset, and wrap it
in a minimal, single-purpose agent harness that calls it as an MCP tool — not a re-run of
NextMove's analyst/inspector/writer pipeline.
